# Политика документации

## Состав документации

Документация системы ТОиР включает:

- `README.md`;
- `openapi/openapi-v1.yaml`;
- `CHANGELOG.md`;
- `docs/operations.md`;
- документы по инцидентам и postmortem;
- `migrations/README.md`;
- `docs/release_checklist.md`.

## Правила обновления

Документация обновляется в той же ветке, где меняется код, конфигурация, API или схема БД.

Изменение API без обновления OpenAPI считается неполным. Изменение миграций без инструкции считается неполным. Изменение конфигурации без обновления `env.example` считается неполным.

## Проверка полноты

Перед выпуском нужно проверить:

- новые endpoint и DTO отражены в OpenAPI;
- новые переменные окружения добавлены в `env.example`;
- миграции описаны в `migrations/README.md` или checklist;
- changelog содержит пользовательски значимые изменения;
- операционные инструкции отражают новые зависимости и проверки.
