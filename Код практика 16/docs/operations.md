# Операционные инструкции

## Запуск сервиса

1. Проверить наличие переменных окружения из `config/env.example`.
2. Проверить доступность PostgreSQL и актуальность миграций.
3. Запустить сервис ТОиР штатным способом для окружения.
4. Убедиться, что сервис отвечает на health endpoint.

## Остановка сервиса

1. Остановить прием нового трафика через балансировщик или orchestrator.
2. Дождаться завершения активных запросов.
3. Остановить процесс сервиса.
4. Проверить отсутствие новых ошибок в логах.

## Проверка health endpoint

Health endpoint должен подтверждать доступность приложения и основных зависимостей. Минимальная проверка включает состояние сервиса, подключение к PostgreSQL и возможность записи диагностического события при необходимости.

## Проверка подключения к БД

Проверить строку подключения `TOIR_DB_CONNECTION`, доступность PostgreSQL и права пользователя на чтение и запись таблиц заявок, нарядов, оборудования и `audit_log`.

## Проверка логов

Логи проверяются по `traceId`, уровню, операции и результату. Для ошибок нужно убедиться, что в записи есть `operation`, `entityType`, `entityId`, `durationMs` и понятное сообщение.

## Проверка метрик

Проверить HTTP-метрики, задержки БД, ошибки аудита, ошибки валидации и конфликты состояния. Значения должны соответствовать профилю нагрузки окружения.

## Действия при росте ошибок

1. Определить, какие endpoint дают рост ошибок.
2. Найти примеры `traceId`.
3. Проверить последний релиз и изменения конфигурации.
4. Проверить состояние PostgreSQL и блокировки.
5. При влиянии на критичные операции инициировать инцидент.
6. При необходимости выполнить откат согласно `RELEASE_PROCESS.md`.
