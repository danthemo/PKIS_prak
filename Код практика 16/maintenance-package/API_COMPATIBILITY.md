# Совместимость API

## Принципы обратной совместимости

REST API системы ТОиР публикуется в пространстве `/api/v1`. Старые поля ответов не удаляются внутри `/api/v1`, даже если они больше не используются новыми клиентами.

Обязательные поля запросов не добавляются без новой версии API. Если новое поле нужно для бизнес-логики, оно вводится как необязательное, получает серверное значение по умолчанию или переносится в `/api/v2`.

Коды ошибок сохраняют семантику. Например, `409 STATE_CONFLICT` означает невозможность выполнить операцию из-за текущего состояния заявки или наряда, а `422 VALIDATION_ERROR` означает ошибку проверки входных данных.

Новые статусы заявок и нарядов добавляются только после анализа клиентов, отчетов и интеграций. OpenAPI обновляется одновременно с кодом, миграциями и контрактными тестами.

## Правила версии

- Ломающие изменения требуют нового пространства `/api/v2`.
- Клиент узнает версию API через URL и заголовок ответа `X-Api-Version`.
- Сервер возвращает `traceId` в каждом успешном и ошибочном ответе.
- Заголовок `X-Api-Version` должен соответствовать версии URL, например `1` для `/api/v1`.

## Ошибки

Все ошибки возвращаются в едином формате `ErrorResponse` с полями `code`, `message`, `traceId` и, при необходимости, `fieldErrors`.

Допустимые коды ошибок:

- `BAD_REQUEST`;
- `UNAUTHORIZED`;
- `FORBIDDEN`;
- `NOT_FOUND`;
- `STATE_CONFLICT`;
- `VALIDATION_ERROR`;
- `INTERNAL_ERROR`.
